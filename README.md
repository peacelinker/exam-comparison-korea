# 시험 비교 분석

`.xlsx` 파일의 날짜형 시트 탭과 I열 입력 상태를 분석해 이번·직전 시험 탭을 추천하고, A·D·G·I열로 지역별 시험 현황과 개인 전환을 비교하는 정적 웹앱입니다.

## 개인정보 보호

> **개인정보가 담긴 엑셀 파일을 저장소에 절대 커밋하지 마세요.**

- 파일은 `File.arrayBuffer()`로 읽고 현재 브라우저 메모리에서만 처리합니다.
- `fetch`, 외부 API, 백엔드, 쿠키, 로컬 스토리지, 분석 추적 도구를 사용하지 않습니다.
- GitHub Pages는 앱 코드만 배포합니다. 업로드한 엑셀과 이름 목록은 사용자의 브라우저 밖으로 나가지 않습니다.
- 새로고침하거나 `새 파일 분석`을 누르면 메모리의 분석 상태가 사라집니다.
- `.gitignore`는 `.xlsx`, `.xls`, `.xlsm`, `.xlsb`를 제외합니다.

## 실행

Node.js 20.19 이상이 필요합니다.

```bash
npm install
npm run dev
```

개발 서버가 안내하는 로컬 주소를 브라우저에서 엽니다.

## 테스트와 빌드

```bash
npm run test
npm run build
```

테스트는 날짜 탭 해석, 7일 경계와 연도 전환, 중복 날짜, 입력률 임계값, A/B/C 추천 규칙, 불완전 탭 건너뛰기, 상태 정규화, 집계, 증감 전환, 중복 이름과 지역 이동, 보고서 형식을 검증합니다.

샘플처럼 개인정보가 있는 파일은 저장소에 넣지 않고 로컬에서만 다음처럼 검산할 수 있습니다. 출력에는 이름 목록이 포함되지 않습니다.

```bash
npm run acceptance -- "C:\path\to\private-file.xlsx" 2026-07-23 0.5
```

## GitHub Pages 배포

`.github/workflows/deploy-pages.yml`이 `main` 브랜치 푸시 또는 수동 실행 시 테스트와 빌드 후 Pages에 배포합니다.

Vite `base`는 다음 두 경우를 자동 처리합니다.

- 일반 저장소: `https://<사용자>.github.io/<저장소>/`
- 사용자 Pages 저장소: `https://<사용자>.github.io/`

필요하면 빌드 시 `VITE_BASE_PATH=/원하는-경로/`로 명시할 수 있습니다. 클라이언트 라우터를 사용하지 않아 새로고침 404 문제도 없습니다.

## 주요 구조

```text
src/
  App.tsx          화면 흐름과 브라우저 상호작용
  core.ts          날짜, 추천, 매칭, 집계 순수 함수
  excel.ts         SheetJS 기반 브라우저 엑셀 파싱
  report.ts        검산 요약과 지정 보고서 출력
  types.ts         재사용 타입과 상태 상수
  core.test.ts     요구된 단위 테스트
scripts/
  acceptance.ts    개인정보 비노출 로컬 인수 검산
.github/workflows/
  deploy-pages.yml GitHub Pages 배포
```

## 판정 원칙

- 데이터 행은 D열에 이름이 있는 2행 이후 행입니다.
- 유효 입력률은 유효 시험 상태 수를 D열 이름 행 수로 나눈 값입니다.
- 빈값과 알 수 없는 값은 `미응시`로 바꾸지 않습니다.
- 유일한 이름은 지역이 바뀌어도 연결하고, 중복 이름은 `지역 + 이름`으로 한 번 더 확인합니다.
- 끝까지 중복이면 개인 전환 분석에서 제외하고 경고합니다.
- 수식은 재계산하지 않으며 파일에 저장된 현재 값만 사용합니다.
